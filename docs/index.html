What is CyberCore?

CyberCore is a modular security platform that lets your team run professional-grade security tooling without sending your source code or vulnerability data to a third party. Think of it as your own private security operations center (SOC), deployable in minutes via Docker or Kubernetes.

The platform is built from independent microservices. You can run the entire stack, or only the pieces you need. Each service exposes a versioned REST API and communicates with the others over HTTP — no shared database, no tight coupling.

Core Capabilities

🔬
SAST Scanning
Static code analysis across Python, Go, JavaScript/TypeScript, and more using 8 open-source tools.
🔐
Auth Service
JWT + refresh token auth with email verification, password reset, brute-force protection, and MFA.
🏢
Organizations
Multi-tenant organization management with role-based access control and fine-grained privileges.
⚙️
Async Workers
Celery-based scan worker runs security tools in the background, deduplicates findings, and persists results.
🛡️
Security Model
httpOnly cookies, Redis-backed token blacklist, zip-bomb protection, RCE prevention, and RBAC.
🗄️
Database Schema
MySQL 8.0 schema with soft deletes, audit columns, composite indexes, and UNIQUE constraints.

Request Flow

Every API request from the dashboard goes through this chain:

Browser
  │
  ├── Vite dev proxy (port 3000)    ← routes by URL prefix
  │
  ├─► auth-service  (:8000)         ← /api/v1/users/**
  │       └── MySQL (users, user_tokens)
  │       └── Redis (token blacklist DB 1)
  │
  ├─► org-service   (:8081)         ← /api/v1/organizations/**
  │       └── MySQL (organizations, roles, members)
  │       └── auth-service (validates JWT on each request)
  │
  └─► scan-service  (:8082)         ← /api/v1/scans/**
          └── MySQL (scan_jobs, scan_findings)
          └── org-service  (privilege check)
          └── auth-service (user identity)
          └── Redis → scan-worker   (Celery task queue)
