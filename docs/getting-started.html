Getting Started

Run CyberCore locally in under 10 minutes. This guide covers prerequisites, service setup, first login, creating an organisation, and running your first scan.

SAST Tool Dependencies

The scan worker invokes external binaries. Install whichever you need:

  • Bandit — pip install bandit
  • Semgrep — pip install semgrep
  • Gitleaks — download binary
  • Trivy — install guide
  • Hadolint — download binary
  • gosec — go install github.com/securego/gosec/v2/cmd/gosec@latest

Missing tools are skipped silently — you don't need all of them to run scans.

Running the Services

Docker — recommended for the full stack

To start every service, database, and the dashboard with a single command, use Docker Compose:

cp .env.example .env   # fill in JWT_SECRET_KEY and DB passwords
docker compose up --build -d

See the Docker & Deployment page for the full guide, environment variable reference, and production notes.

Or run each service directly as an independent Python process (separate terminals):

1. Auth Service

cd services/auth-service
pip install -r requirements.txt
# Set required env vars (see below)
python start_service.py
# Runs on http://localhost:8000

2. Organization Service

cd services/organization-service
pip install -r requirements.txt
python start_service.py
# Runs on http://localhost:8081

3. Scan Service

cd services/scan-service
pip install -r requirements.txt
python start_service.py
# Runs on http://localhost:8082

4. Scan Worker (Celery)

cd workers/scan-worker
pip install -r requirements.txt
celery -A src.celery_app worker -Q sast --loglevel=info
# Picks up scan tasks from Redis

5. Dashboard

cd dashboard
npm install
npm run dev
# Runs on http://localhost:3000
# Automatically proxies API calls to the backend services
Create Tables First

Set DB_CREATE_TABLES=true the first time you run each service to let SQLAlchemy create the schema. Use the SQL files in database/sql/tables/ for production — they include comments, constraints, and indexes that SQLAlchemy's create_all() may handle differently.

First Steps After Launch

1

Register an account

Open http://localhost:3000/register and fill in your email, full name, and a password that meets the policy (12+ chars, uppercase, lowercase, number, special character). You'll receive a verification email — click the link before you can log in.

Local email

Without SMTP configured, the verification token is printed to the auth-service console log. Copy the token and visit /verify-email?token=YOUR_TOKEN manually.

2

Log in

After email verification, log in at http://localhost:3000/login. The server sets two httpOnly cookies: a 15-minute access_token and a 7-day refresh_token. These are renewed automatically — you won't be logged out unless you explicitly click Logout.

3

Create an Organisation

On the dashboard, click Create Organisation. Pick a name and a unique slug (URL-friendly identifier, e.g. my-company). You become the Owner automatically and get all privileges.

4

Run Your First Scan

Navigate to the Scans tab in your organisation. Choose Scan Git Repo and enter a public repository URL, or Upload ZIP to scan local code. The scan is queued immediately and picked up by the worker within seconds.

Running Your First Scan via API

If you prefer curl:

# 1. Login (saves cookies to file)
curl -c cookies.txt -X POST http://localhost:8000/api/v1/users/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"YourP@ssword1"}'

# 2. Submit a git scan
curl -b cookies.txt -X POST \
  http://localhost:8082/api/v1/scans/organizations/my-company/scans/git \
  -H "Content-Type: application/json" \
  -d '{"name":"My first scan","target_url":"https://github.com/owner/repo"}'
# Returns: {"id":"...","status":"queued",...}

# 3. Poll for results
curl -b cookies.txt \
  http://localhost:8082/api/v1/scans/organizations/my-company/scans/JOB_ID

# 4. Retrieve findings (when status = completed)
curl -b cookies.txt \
  "http://localhost:8082/api/v1/scans/organizations/my-company/scans/JOB_ID/findings?limit=50"
You're all set!
