Contributing

CyberCore is open source and welcomes contributions. This guide covers the workflow, code style, how to add a new scanning tool, and how to report security vulnerabilities.

Contribution Workflow

1

Fork & clone

git clone https://github.com/YOUR_USERNAME/cybercore.git
cd cybercore
git remote add upstream https://github.com/ORIGINAL/cybercore.git
2

Create a feature branch

git checkout -b feat/my-feature   # new feature
git checkout -b fix/broken-thing  # bug fix
git checkout -b docs/update-api   # documentation

Branch naming: feat/, fix/, docs/, refactor/, perf/, test/, chore/.

3

Make your changes

Keep each PR focused on a single concern. Mixing unrelated changes makes review harder and increases the chance of regressions.

4

Test locally

# Quick syntax check (no pytest yet)
python -m py_compile services/scan-service/src/**/*.py
python -m py_compile workers/scan-worker/src/**/*.py
5

Open a pull request

Target branch: main. Describe:

  • What the change does
  • Why it's needed (link the issue if one exists)
  • How to test it
  • Any breaking changes

Security-related PRs go through an additional review pass. Mention [security] in the title.

Code Style

Python (all backend services + worker)

  • Formatter: Black (line length 100). Run black . before committing.
  • Imports: isort with Black profile. isort --profile black .
  • Type hints: required on all public functions and service methods. Use str | None syntax (Python 3.10+).
  • Docstrings: short module-level docstrings on new files. Function docstrings for non-obvious logic only.
  • Prefer explicit over clever. A clear if/else is better than a one-liner that requires a comment to understand.

SQLAlchemy

  • Use SQLAlchemy 2.0 Mapped + mapped_column style (not the legacy Column API).
  • Bulk inserts: use db.execute(insert(Model), rows), not db.add() in a loop.
  • No lazy loading across service boundaries. If you need related objects, eager-load them in the same query.

FastAPI

  • Use Depends() for all cross-cutting concerns (auth, DB sessions, service instances).
  • Never put business logic in route functions — route functions delegate to service classes.
  • All route functions must have explicit response_model or status_code.

JavaScript / React

  • ESModules only ("type": "module" in package.json).
  • Functional components with hooks. No class components.
  • Keep components focused; split at ~150 lines.

Commit Messages

Use Conventional Commits:

<type>(<scope>): <short description>

[optional body — why, not what]

[optional footer: BREAKING CHANGE: ..., Closes #123]

Types

TypeWhen to use
featNew feature
fixBug fix
perfPerformance improvement
refactorCode change that doesn't fix a bug or add a feature
docsDocumentation only
testAdding or updating tests
choreDependencies, config, CI
securitySecurity fixes (use instead of fix for CVEs/vulns)

Examples

feat(scan-service): add scan status stats endpoint
fix(auth): reset failed_login_attempts on successful login
security(worker): validate git URL scheme before clone (RCE prevention)
perf(scan-service): replace 3 COUNT queries with single GROUP BY
docs: add architecture page to documentation site

Adding Documentation Pages

The documentation site is static HTML — no build step required. To add a new page:

1

Copy the template

cp documentation/_template.html documentation/my-new-page.html
2

Add the page to nav.js

Open documentation/assets/nav.js and add your page to the NAV_ITEMS array:

// In the appropriate section:
{ label: "My New Page", href: "my-new-page.html" }

The nav updates everywhere automatically — no other file changes needed.

3

Write your content

Fill in the <h1>, <p class="lead">, and content sections. Use the shared CSS classes documented in the template.

Adding a New Scanner Tool

To integrate a new SAST tool into the worker pipeline:

1

Write the runner

Create workers/scan-worker/src/runners/mytool_runner.py:

"""MyTool runner — invokes the mytool binary and returns raw JSON output."""
import subprocess
from pathlib import Path


def run(source_dir: Path) -> str:
    """Run mytool and return the raw JSON string."""
    result = subprocess.run(
        ["mytool", "--format", "json", str(source_dir)],
        capture_output=True,
        text=True,
        timeout=300,
    )
    # Exit code 1 typically means "findings found" — not an error.
    # Exit code 2+ is a tool error.
    if result.returncode >= 2:
        raise RuntimeError(f"mytool exited with {result.returncode}: {result.stderr.strip()}")
    return result.stdout
2

Write the parser

Create workers/scan-worker/src/parsers/mytool_parser.py:

"""MyTool parser — converts raw tool output into the CyberCore finding format."""
import hashlib
import json
import uuid
from pathlib import Path


def parse(raw: str, source_dir: Path) -> list[dict]:
    if not raw.strip():
        return []
    try:
        data = json.loads(raw)
    except json.JSONDecodeError:
        return []

    findings = []
    for item in data.get("results", []):
        file_path = item.get("file", "")
        line      = item.get("line")
        rule_id   = item.get("rule_id", "unknown")

        fingerprint = hashlib.sha256(
            f"mytool:{rule_id}:{file_path}:{line}".encode()
        ).hexdigest()

        findings.append({
            "id":          str(uuid.uuid4()),
            "tool":        "mytool",
            "rule_id":     rule_id,
            "severity":    _map_severity(item.get("severity", "medium")),
            "confidence":  None,
            "title":       item.get("message", ""),
            "message":     item.get("description", ""),
            "file_path":   str(Path(file_path).relative_to(source_dir)) if file_path else "",
            "line_start":  line,
            "line_end":    line,
            "code_snippet": item.get("code"),
            "cwe":         item.get("cwe"),
            "owasp":       None,
            "fingerprint": fingerprint,
        })
    return findings


def _map_severity(raw: str) -> str:
    return {"CRITICAL": "critical", "HIGH": "high", "MEDIUM": "medium",
            "LOW": "low", "INFO": "info"}.get(raw.upper(), "medium")
3

Register in the task

Edit workers/scan-worker/src/tasks/sast.py:

from ..runners import mytool_runner   # add to imports
from ..parsers import mytool_parser   # add to imports

# In run_sast_scan(), inside the "Run tools" section:
collect("mytool", mytool_runner.run, mytool_parser.parse, source_dir)

# Or conditionally:
if has_go:   # only for Go projects
    collect("mytool", mytool_runner.run, mytool_parser.parse, source_dir)
4

Update the documentation

Add the new tool to the tools table in SAST Worker docs and the README.

Security Vulnerabilities

Do NOT open a public GitHub issue for security bugs

If you find a vulnerability in CyberCore itself, please report it privately. Public disclosure before a patch is ready puts all users at risk.

Report security vulnerabilities by email to: security@cybercore.dev (update with your actual contact).

Please include:

  • Description of the vulnerability
  • Steps to reproduce
  • Affected versions
  • Potential impact
  • Suggested fix (optional but appreciated)

We aim to respond within 48 hours and will credit responsible disclosure in the changelog.
