SAST Worker

Celery Redis Queue: sast

The scan-worker is a Celery process that runs all security tools asynchronously. It has no HTTP API — it listens on the Redis sast queue and processes scan jobs dispatched by scan-service.

Missing tools are skipped gracefully

If a tool binary is not installed (raises FileNotFoundError), the worker logs an info message and continues with the other tools. You don't need all 8 tools to run scans — install only the ones relevant to your stack.

Project Type Detection

Before running any tools, the worker detects which languages and dependency manifests are present. This is done in a single os.walk pass over the source directory:

def _detect_extensions(directory: Path, extensions: set[str]) -> set[str]:
    found: set[str] = set()
    # Noisy directories are skipped entirely
    skip_dirs = {".git", "node_modules", ".venv", "venv", "__pycache__", "dist", "build"}
    for root, dirnames, filenames in os.walk(directory):
        dirnames[:] = [d for d in dirnames if d not in skip_dirs]
        for name in filenames:
            dot = name.rfind(".")
            if dot == -1: continue
            ext = name[dot:].lower()
            if ext in extensions:
                found.add(ext)
                if len(found) == len(extensions):
                    return found  # early exit — all targets found
    return found

Execution Pipeline

1. Load job from DB; flip status → "running" (atomic — cancelled/deleted jobs exit early)

2. Prepare source code:
     git_url  → validate URL → git clone --depth 1 -- URL dest
     upload   → validate ZIP (zip-slip + zip-bomb) → extract to workspace

3. Single-pass extension detection (skip node_modules, .git, etc.)

4. Run tools (all applicable; errors are non-fatal per tool):
     ├─ bandit    (always)
     ├─ semgrep   (always)
     ├─ gitleaks  (always, custom inline error handling)
     ├─ trivy     (always)
     ├─ hadolint  (always)
     ├─ pip-audit (if has_py_deps)
     ├─ npm audit (if has_pkg_json)
     └─ gosec     (if has_go)

5. Deduplicate: filter all_findings by fingerprint hash set

6. Persist:
     ├─ INSERT INTO scan_findings ... (Core insert, 500-row chunks)
     └─ UPDATE scan_jobs SET status='completed', findings_count=N

7. Cleanup workspace directory (always, even on failure)

Deduplication

Multiple tools may report the same vulnerability (e.g. Semgrep and Bandit both catch the same SQL injection). Each finding has a fingerprint that is unique to the combination of tool + rule + file + location. The worker deduplicates in memory before inserting:

seen: set[str] = set()
unique_findings: list[dict] = []
for f in all_findings:
    fp = f["fingerprint"]
    if fp not in seen:
        seen.add(fp)
        unique_findings.append(f)

The database also enforces a UNIQUE(scan_job_id, fingerprint) constraint as a second layer — concurrent workers or retries cannot insert duplicates.

Fingerprinting

Each parser generates a fingerprint for its findings. The fingerprint is a SHA-256 hash of the fields that uniquely identify a vulnerability location:

import hashlib

def make_fingerprint(tool: str, rule_id: str, file_path: str,
                     line_start: int | None) -> str:
    raw = f"{tool}:{rule_id}:{file_path}:{line_start}"
    return hashlib.sha256(raw.encode()).hexdigest()

The same finding in the same file at the same line will always produce the same fingerprint — regardless of which run found it. This makes the UNIQUE constraint meaningful across retries.

Git Clone Security

User-supplied git URLs are validated before cloning. The validation runs twice: once in the API (schema validator) and once in the worker (before the subprocess call).

Allowed URL schemes

_ALLOWED_GIT_SCHEMES = ("http", "https", "git")
# Blocked: ext::, file://, ssh://, scp-style user@host:path

Clone command

subprocess.run(
    ["git", "clone", "--depth", "1", "--single-branch", "--", safe_url, str(dest)],
    env={**os.environ, "GIT_TERMINAL_PROMPT": "0"},  # never block for credentials
    capture_output=True,
    text=True,
    timeout=120,
)
  • -- — separates git options from positional args, preventing URL-as-option injection
  • GIT_TERMINAL_PROMPT=0 — prevents the worker from hanging indefinitely waiting for credentials on private repos
  • timeout=120 — clones that stall (network issues, huge repos) are killed after 2 minutes
  • --depth 1 — shallow clone; fetches only the latest commit, not full history

ZIP Extraction Security

Zip-slip (path traversal)

for info in zf.infolist():
    name = info.filename
    # Level 1: string check (cheap)
    if name.startswith(("/", "\\")) or any(p in ("..",) for p in Path(name).parts):
        raise RuntimeError(f"ZIP rejected: unsafe entry path '{name}'")

    # Level 2: resolved path check (handles symlink tricks)
    target = (dest / name).resolve()
    try:
        target.relative_to(dest_resolved)
    except ValueError:
        raise RuntimeError(f"ZIP rejected: entry escapes target '{name}'")

Zip-bomb (size limits)

# Checked before any extraction
if len(infos) > max_entries:          # default 200,000
    raise RuntimeError("too many entries")

total_uncompressed = 0
for info in infos:
    total_uncompressed += info.file_size
    if total_uncompressed > max_uncompressed_bytes:  # default 5 GiB
        raise RuntimeError("uncompressed size exceeds limit")

Both limits are checked on infolist() metadata before extractall() is called. A zip-bomb is rejected without decompressing a single byte.

Error Handling

Tool errors (non-fatal)

Each tool runs inside _run_tool(). Tool failures are caught and collected; they do not abort the scan:

def _run_tool(name, runner_fn, parser_fn, *args):
    try:
        raw      = runner_fn(*args)
        findings = parser_fn(raw, args[-1])
        return findings, None
    except FileNotFoundError:
        log.info("%s not installed — skipping", name)
        return [], None
    except Exception as exc:
        log.warning("%s failed: %s", name, exc)
        return [], f"{name}: {exc}"

Tool errors are joined and stored in scan_jobs.error_message. The scan status becomes completed (not failed) — partial results are better than nothing.

Fatal task errors

If the task raises an unhandled exception (bad DB connection, corrupt ZIP, etc.), the outer try/except catches it, sets the job to failed with the error message, and re-raises so Celery knows the task failed:

except Exception as exc:
    log.exception("SAST task failed for job %s", job_id)
    try:
        with db_session() as db:
            job = db.query(ScanJob).filter_by(id=job_id).first()
            if job:
                job.status        = "failed"
                job.error_message = str(exc)
                job.completed_at  = datetime.now(tz=timezone.utc)
    except Exception:
        pass    # DB itself may be down; don't mask the original error
    raise       # let Celery see the failure

Starting the worker

cd workers/scan-worker
celery -A src.celery_app worker \
  -Q sast \
  --loglevel=info \
  --concurrency=2   # number of parallel scans

On Windows, Celery falls back to the solo pool (single process) automatically. On Linux/macOS it uses prefork. Set --concurrency based on available RAM — each scan can use significant memory running 8 tools simultaneously.
