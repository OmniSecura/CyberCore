Database Schema

MySQL 8.0. All tables use InnoDB, UTF-8mb4, and soft deletes. Schema files live in database/sql/tables/. Apply the migration in database/sql/migrations/ on running databases.

Dev vs Production

In development, set DB_CREATE_TABLES=true and SQLAlchemy's create_all() builds the schema automatically. For production, use the SQL files — they include comments, constraints, and CHECK expressions that create_all() may render differently across database versions.

users

Owned by auth-service. The source of truth for all user identities.

CREATE TABLE users (
    id                      CHAR(36)        NOT NULL DEFAULT (UUID()),
    email                   VARCHAR(255)    NOT NULL,
    email_verified          BOOLEAN         NOT NULL DEFAULT FALSE,
    password_hash           VARCHAR(255)    NULL,       -- NULL for OAuth-only accounts
    full_name               VARCHAR(255)    NOT NULL,
    avatar_url              VARCHAR(500)    NULL,

    -- Account status
    is_active               BOOLEAN         NOT NULL DEFAULT TRUE,
    is_superadmin           BOOLEAN         NOT NULL DEFAULT FALSE,

    -- MFA (TOTP)
    mfa_enabled             BOOLEAN         NOT NULL DEFAULT FALSE,
    mfa_secret              VARCHAR(64)     NULL,

    -- Brute-force lockout
    failed_login_attempts   INT             NOT NULL DEFAULT 0,
    locked_until            DATETIME        NULL,

    -- Audit
    last_login_at           DATETIME        NULL,
    last_login_ip           VARCHAR(45)     NULL,
    created_at              DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at              DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at              DATETIME        NULL,    -- soft-delete

    PRIMARY KEY (id),
    UNIQUE KEY uq_users_email (email)
);

user_tokens

Stores hashed one-time tokens for email verification and password resets. Only the SHA-256 hash is persisted — the plaintext token is sent via email and never stored.

CREATE TABLE user_tokens (
    id          CHAR(36)        NOT NULL DEFAULT (UUID()),
    user_id     CHAR(36)        NOT NULL,
    token_hash  VARCHAR(255)    NOT NULL,   -- SHA-256(plaintext)
    token_type  VARCHAR(50)     NOT NULL,   -- 'email_verification' | 'password_reset' | 'org_invite'
    expires_at  DATETIME        NOT NULL,
    used_at     DATETIME        NULL,       -- NULL = unused; set when token consumed

    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    PRIMARY KEY (id),
    UNIQUE KEY uq_user_tokens_hash (token_hash),
    CONSTRAINT fk_user_tokens_user
        FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);

scan_jobs

Owned by scan-service and scan-worker. One row per scan submission.

CREATE TABLE scan_jobs (
    id                  CHAR(36)        NOT NULL DEFAULT (UUID()),
    organization_id     CHAR(36)        NOT NULL,   -- no FK (cross-service boundary)
    created_by          CHAR(36)        NOT NULL,   -- user_id; no FK (cross-service)

    name                VARCHAR(255)    NOT NULL,
    scan_type           VARCHAR(32)     NOT NULL DEFAULT 'sast',

    -- Lifecycle: queued → running → completed | failed | cancelled
    status              VARCHAR(32)     NOT NULL DEFAULT 'queued',

    target_type         VARCHAR(32)     NOT NULL,   -- 'git_url' | 'upload'
    target_url          TEXT            NULL,
    target_path         TEXT            NULL,

    celery_task_id      VARCHAR(255)    NULL,

    started_at          DATETIME        NULL,
    completed_at        DATETIME        NULL,
    error_message       TEXT            NULL,

    -- Denormalised: avoids JOIN on list queries
    findings_count      INT             NOT NULL DEFAULT 0,
    extra               JSON            NULL,

    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at          DATETIME        NULL,

    PRIMARY KEY (id),

    CONSTRAINT chk_scan_jobs_status
        CHECK (status IN ('queued','running','completed','failed','cancelled')),
    CONSTRAINT chk_scan_jobs_type
        CHECK (scan_type IN ('sast','dast')),
    CONSTRAINT chk_scan_jobs_target_type
        CHECK (target_type IN ('git_url','upload'))
);

-- Composite index covers: WHERE org_id = ? AND deleted_at IS NULL ORDER BY created_at DESC
-- Also covers queries filtering only on organization_id (leftmost column).
CREATE INDEX ix_scan_jobs_org_active_created ON scan_jobs(organization_id, deleted_at, created_at);
CREATE INDEX idx_scan_jobs_status            ON scan_jobs(status);
CREATE INDEX idx_scan_jobs_created_by        ON scan_jobs(created_by);
CREATE INDEX idx_scan_jobs_created_at        ON scan_jobs(created_at);

scan_findings

Owned by scan-service and written by scan-worker. One row per unique finding per scan.

CREATE TABLE scan_findings (
    id          CHAR(36)        NOT NULL DEFAULT (UUID()),
    scan_job_id CHAR(36)        NOT NULL,

    tool        VARCHAR(32)     NOT NULL,   -- 'bandit'|'semgrep'|'gitleaks'|'trivy'|etc.
    rule_id     VARCHAR(256)    NOT NULL,
    severity    VARCHAR(16)     NOT NULL,   -- 'critical'|'high'|'medium'|'low'|'info'
    confidence  VARCHAR(16)     NULL,

    title       VARCHAR(1024)   NOT NULL,
    message     MEDIUMTEXT      NOT NULL,   -- full description

    file_path   VARCHAR(2048)   NOT NULL,
    line_start  INT             NULL,
    line_end    INT             NULL,
    code_snippet MEDIUMTEXT     NULL,

    cwe         VARCHAR(256)    NULL,       -- e.g. 'CWE-89'
    owasp       VARCHAR(128)    NULL,       -- e.g. 'A03:2021'

    -- SHA-256 of (tool:rule_id:file_path:line_start)
    -- Ensures one finding per location per scan, even across retries
    fingerprint VARCHAR(64)     NOT NULL,

    created_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    PRIMARY KEY (id),

    -- DB-level dedup guarantee: concurrent workers cannot insert duplicates
    CONSTRAINT uq_findings_job_fp UNIQUE (scan_job_id, fingerprint),

    CONSTRAINT fk_findings_job
        FOREIGN KEY (scan_job_id) REFERENCES scan_jobs (id) ON DELETE CASCADE
);

CREATE INDEX idx_findings_scan_job_id ON scan_findings(scan_job_id);
CREATE INDEX idx_findings_severity    ON scan_findings(severity);

organizations

Owned by organization-service. Abbreviated schema — see the service's SQL files for the full definition including roles and members tables.

CREATE TABLE organizations (
    id                  CHAR(36)        NOT NULL DEFAULT (UUID()),
    organization_name   VARCHAR(255)    NOT NULL,
    organization_slug   VARCHAR(100)    NOT NULL,   -- URL-friendly, globally unique

    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at          DATETIME        NULL,

    PRIMARY KEY (id),
    UNIQUE KEY uq_org_slug (organization_slug)   -- freed on soft delete
);

Conventions

Primary keys

All tables use CHAR(36) UUID primary keys generated by UUID() in MySQL or uuid.uuid4() in Python. UUIDs are:

  • Globally unique across databases (safe for future sharding)
  • Safe to expose in URLs (no sequential ID enumeration)
  • Compatible with soft-delete patterns (no re-use)

Soft deletes

Main entity tables (users, organizations, scan_jobs) use deleted_at DATETIME NULL. A row is "deleted" when deleted_at IS NOT NULL. All queries filter on deleted_at IS NULL. Hard deletes are avoided — historical data is preserved for audits.

Audit columns

Tables that use AuditMixin (SQLAlchemy) get: created_at, updated_at, deleted_at. Tables that only need timestamps (no soft delete) use TimestampMixin: created_at, updated_at.

Cross-service references

There are no foreign keys across service boundaries. For example, scan_jobs.organization_id references an org UUID, but there is no FK constraint — org validation is handled by the organization-service via HTTP. This is intentional: it keeps services independently deployable.

Migration Guide

An idempotent migration script is provided for applying schema changes to a running production database:

mysql -u root -p cybercore \
  < database/sql/migrations/2026_05_14_scan_security_fixes.sql

The migration is safe to re-run. It checks information_schema before each DDL statement so it skips changes that were already applied:

-- Example guard from the migration:
SELECT COUNT(*) INTO @idx_exists
FROM information_schema.STATISTICS
WHERE table_schema = DATABASE()
  AND table_name   = 'scan_jobs'
  AND index_name   = 'ix_scan_jobs_org_active_created';

SET @sql = IF(@idx_exists = 0,
    'CREATE INDEX ix_scan_jobs_org_active_created ON scan_jobs(organization_id, deleted_at, created_at)',
    'SELECT "index already exists — skipping"');
PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt;

Changes in migration 2026-05-14

  • Added: ix_scan_jobs_org_active_created composite index on scan_jobs
  • Dropped: idx_scan_jobs_org_id (redundant — composite covers it)
  • Added: uq_findings_job_fp UNIQUE(scan_job_id, fingerprint) on scan_findings
Check for duplicates before adding UNIQUE

The migration includes a pre-flight check that reports how many duplicate (scan_job_id, fingerprint) pairs exist before attempting to add the UNIQUE constraint. Adding UNIQUE to a table with duplicates fails immediately. If your production database has duplicates, use the provided cleanup DELETE statement (commented out in the migration) to deduplicate first.
